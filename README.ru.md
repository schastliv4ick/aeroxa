# Aeroxa Legal RAG (MVP)

Бэкенд, отвечающий на юридические вопросы по праву РФ для иностранных предпринимателей.
Вопрос на русском, китайском или английском сопоставляется с корпусом федеральных актов,
и LLM формулирует ответ **только** из найденных статей, ссылаясь на каждую — либо
воздерживается и передаёт вопрос юристу.

Полное техническое задание, включая то, что осознанно вынесено за рамки MVP:
[docs/SPEC.md](docs/SPEC.md) (на английском).

```
вопрос ─► сжатие ─► гибридный поиск BGE-M3 ─► фильтр редакции ─► реранк ─► диверсификация ─┬─► LLM ─► ответ со ссылками
(любой язык) (если есть история)  (Qdrant, dense+sparse RRF)                               └─► воздержаться + эскалация
```

Стартовый корпус — пять федеральных актов: **3961 фрагмент по 1209 статьям**, каждый в
действующей редакции. Кросс-язычный поиск проверен: 有限责任公司的最低注册资本是多少？
находит Статью 14 «Уставный капитал общества».

## Быстрый старт

Команды даны для **macOS / Linux** (bash или zsh) и для **Windows** (PowerShell).
Выполняйте их из корня репозитория.

### 1. Инфраструктура

Одинаково на всех платформах:

```bash
docker compose up -d qdrant postgres
```

Если команда падает с `dial tcp: lookup registry-1.docker.io: no such host`, значит Docker
Hub недоступен из вашей сети — см. [Диагностику](#диагностика).

### 2. Окружение Python

Требуется Python 3.11 или новее.

**macOS / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**Windows (PowerShell)**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install --extra-index-url https://download.pytorch.org/whl/cpu -r requirements.txt
```

Два важных отличия:

- Структура виртуального окружения различается: на macOS и Linux создаётся `.venv/bin/`,
  на Windows — `.venv\Scripts\`. По другому пути скрипта активации просто нет.
- `--extra-index-url` фиксирует сборки PyTorch только под CPU. Используйте его на Windows
  и Linux, где обычный пакет может подтянуть библиотеки CUDA, которые вам не нужны. На
  macOS он просто не нужен: сборок PyTorch с CUDA под macOS не существует, поэтому пакет с
  PyPI и так только CPU/MPS. Указать флаг там не вредно, но бессмысленно.

Если PowerShell отказывается запускать скрипт активации, разрешите это для текущей сессии:
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned`.

После активации `python` на обеих платформах указывает на виртуальное окружение, поэтому
все команды ниже одинаковы.

### 3. Конфигурация

**macOS / Linux**

```bash
cp .env.example .env
```

**Windows (PowerShell)**

```powershell
Copy-Item .env.example .env
```

Затем задайте `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`. В продакшене они должны
указывать на self-hosted OpenAI-совместимый эндпоинт внутри периметра — см.
[Конфиденциальность](#конфиденциальность).

### 4. Сборка корпуса

```bash
python -m ingest.cli run --act fz-14-ooo
```

Первый запуск скачивает ~2,3 ГБ весов моделей, а затем считает эмбеддинги всех статей на
CPU. Ожидайте десятки минут на один акт и часы на полный корпус. Загруженный HTML
кэшируется в `data/raw/`, поэтому повторные запуски не обращаются к сети.

### 5. Запуск сервиса

```bash
python -m app.main
```

Интерактивный API: `http://localhost:8000/docs`.

## Как задать вопрос

Тело запроса содержит кириллицу, поэтому способ отправки зависит от вашей оболочки.

**macOS / Linux** — одинарные кавычки сохраняют JSON как есть:

```bash
curl -s localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "Каков минимальный размер уставного капитала ООО?"}'
```

**Windows (PowerShell)** — используйте `Invoke-RestMethod` и обязательно указывайте
`charset=utf-8`, иначе кириллица испортится:

```powershell
Invoke-RestMethod -Uri http://localhost:8000/ask -Method Post `
  -ContentType 'application/json; charset=utf-8' `
  -Body '{"question": "Каков минимальный размер уставного капитала ООО?"}'
```

**Не используйте** голый `curl` в Windows PowerShell: это псевдоним для
`Invoke-WebRequest`, который не принимает `-s`, `-H` и `-d`. Если нужен настоящий curl,
вызывайте `curl.exe` явно.

**Универсальный способ без проблем с кодировкой** — положите тело запроса в файл в UTF-8 и
отправьте его. Так console-кодировка не мешает; на Windows это самый надёжный вариант:

```bash
curl -s localhost:8000/ask -H "Content-Type: application/json" -d @question.json
```

```jsonc
{
  "answer": "Минимальный размер уставного капитала общества с ограниченной ответственностью составляет 10 000 рублей (Статья 14 Федерального закона «Об обществах с ограниченной ответственностью») [1].",
  "language": "ru",
  "abstained": false,
  "escalate": false,
  "citations": [
    {"n": 1, "act_title": "Об обществах с ограниченной ответственностью", "article_number": "14",
     "revision_index": 57, "revision_date": "2026-08-04", "url": "…", "score": 0.94, "snippet": "…"}
  ],
  "latency_ms": 4210
}
```

Эндпоинты:

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/ask` | Полный конвейер: поиск + генерация по контексту + ссылки на статьи |
| `POST` | `/search` | Только поиск — для отладки полноты выдачи и последующих замеров |
| `GET` | `/health` | Доступность Qdrant, размер корпуса, загрузка моделей, адрес LLM |

Многошаговый диалог: передайте предыдущие реплики в `history`; бэкенд сожмёт уточняющий
вопрос в самостоятельный перед поиском. Сам сервис остаётся stateless.

Если найденного недостаточно для ответа, `/ask` возвращает `abstained: true` и
`escalate: true` с сообщением на языке пользователя. Система никогда не догадывается — это
требование «ноль галлюцинаций», а разрыв закрывает юрист в контуре.

`ABSTAIN_THRESHOLD` по умолчанию равен **0.05** — намного ниже, чем кажется разумным. Это
измеренное, а не угаданное значение: реранкер оценивает пару «китайский вопрос — русская
статья» в 4–8 раз ниже, чем русскую пару, *даже когда поиск отработал идеально*. Поэтому
порог, выглядящий безопасным на русских примерах, полностью отсекает верные ответы на
китайском. Вопросы не по теме получают оценку около нуля, так что более высокий порог не
даёт защиты — только ложные отказы. Полные измерения: [docs/SPEC.md §4](docs/SPEC.md).
Не повышайте порог, не повторив эту калибровку.

## Управление корпусом

Одинаково на всех платформах:

```bash
python -m ingest.cli list                 # реестр актов и какие nd уже определены
python -m ingest.cli probe 102051516      # заголовок, список редакций, число статей
python -m ingest.cli find --act gk-rf-1   # найти nd перебором пространства идентификаторов
python -m ingest.cli run --dry-run        # разобрать и нарезать без индексации
python -m ingest.cli run                  # проиндексировать все акты с известным nd
```

Акты описаны в [ingest/acts.yaml](ingest/acts.yaml). У всех пяти уже проставлен проверенный
`nd`, поэтому `run` работает сразу; `find` нужен для добавления новых актов.

### Поддержание актуальных редакций

Каждый акт загружается с **наибольшим** индексом редакции — это и есть действующая
редакция; каждый фрагмент несёт `revision_index`, `revision_date` и изменяющий закон.
Повторный запуск `ingest.cli run` после поправки добавляет новую редакцию и переводит
предыдущую в `in_force: false`: она исчезает из поиска, но остаётся для аудита.

ТЗ называет устаревшие редакции «источником ошибок №1». Две честные оговорки:

- **Бесплатный официальный источник — слабое звено.** Консолидация в ИПС может отставать
  от фактически действующего текста, а `publication.pravo.gov.ru` публикует акты только в
  подписанном виде. Слой загрузки построен так, чтобы ConsultantPlus/Гарант/cntd можно
  было подставить, не трогая нарезку, индексацию и поиск — но до тех пор не выводите
  юриста из контура.
- **Поиск на портале отдаёт HTTP 500,** поэтому идентификаторы документов нельзя найти
  запросом. `ingest.cli find` перебирает диапазон идентификаторов; они примерно
  хронологичны по дате публикации, так что интервал вокруг даты подписания сокращает
  перебор до нескольких сотен запросов. У каждого акта есть регулярное выражение
  `title_match`, которое проверяется до индексации: неверный или переназначенный `nd`
  прерывает загрузку, а не отравляет корпус незаметно.

## Конфиденциальность

Эмбеддинги и реранкинг всегда считаются локально — на этих этапах ни корпус, ни вопрос не
покидают машину. Клиент LLM говорит по OpenAI-совместимому протоколу, поэтому его можно
направить на self-hosted vLLM или Ollama. В `.env.example` указана конфигурация OpenRouter
**только для разработки**: этот эндпоинт отправляет текст третьей стороне и должен быть
заменён на эндпоинт внутри периметра до того, как в систему попадут данные клиентов
(152-ФЗ, слайд 2 ТЗ).

## Производительность на CPU

BGE-M3 и bge-reranker-v2-m3 — модели примерно на 560 млн параметров. Ориентиры на машине
без GPU: 0,3–1 с на эмбеддинг запроса, 2–5 с на реранк 40 кандидатов и часы на индексацию
большого корпуса. Индексация — разовая операция. Задержку запроса определяет реранкер:
уменьшите `RETRIEVE_TOP_K` или поставьте `RERANK_ENABLED=false`, разменяв качество поиска
на скорость.

На Apple Silicon пакет PyTorch с PyPI включает бэкенд Metal (MPS). Использует ли его
реально стек эмбеддингов, зависит от того, как FlagEmbedding выбирает устройство, поэтому
замерьте время вызова `/search`, а не принимайте ускорение на веру. На CPU оставьте
`USE_FP16=false` — половинная точность нужна для GPU и на CPU работает медленнее.

## Диагностика

**Docker Hub недоступен** (`lookup registry-1.docker.io: no such host`). Частая ситуация в
российских сетях. Либо настройте зеркало реестра в Docker Desktop → Settings → Docker
Engine:

```json
{ "registry-mirrors": ["https://mirror.gcr.io"] }
```

(подставьте зеркало, доступное именно из вашей сети — их публикуют несколько российских
облачных провайдеров), либо откажитесь от Docker и запустите Qdrant из релизного бинарника.
Postgres не обязателен: оставьте `DATABASE_URL` пустым, и сервис будет работать без журнала
запросов.

**Загрузка моделей падает с `No space left on device` или просто `OSError: Can't load the
model`.** BGE-M3 и реранкеру вместе нужно около 9 ГБ кэша, потому что Hugging Face хранит
все опубликованные форматы весов. Перенесите кэш на диск, где есть место:

**macOS / Linux**

```bash
export HF_HOME=/Volumes/data/hf-cache
```

**Windows (PowerShell)**

```powershell
$env:HF_HOME = "D:\hf-cache"
```

Задайте это именно как переменную окружения в оболочке **до** запуска процесса: `.env`
читает само приложение, а не библиотеки Hugging Face. Чтобы закрепить настройку, добавьте
строку `export` в `~/.zshrc` (macOS) либо выполните на Windows
`[Environment]::SetEnvironmentVariable('HF_HOME', 'D:\hf-cache', 'User')`.

**Загрузка зависает или падает внутри `xet_get`.** Отключите транспорт Xet у Hugging Face:
`HF_HUB_DISABLE_XET=1` (в PowerShell — `$env:HF_HUB_DISABLE_XET = "1"`).

**PowerShell блокирует `Activate.ps1`.** Разрешите скрипты только для текущей сессии:
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned`.

**Кириллица в запросе превращается в `?` или вызывает ошибку разбора JSON.** Ваша консоль
работает не в UTF-8. Отправьте тело из файла в UTF-8 через `-d @question.json` либо
используйте `Invoke-RestMethod` с `charset=utf-8`, как показано выше.

## Тесты

```bash
python -m pytest
```

59 тестов покрывают разбор документов, нарезку, векторное хранилище, контракт API,
диверсификацию контекста и калибровку воздержания. Ни один из них не требует Docker,
моделей или сети.

## Что не входит в MVP

MCP-сервер, очередь проверки юристом, профиль клиента и slot-filling, дообучение LoRA и
харнесс оценки качества (RAGAS, nDCG, LLM-as-judge). Рекомендуемый порядок работ — в
[docs/SPEC.md §8](docs/SPEC.md). Харнесс оценки стоит сделать первым: без него ни одно
утверждение о качестве ответов нельзя измерить.
